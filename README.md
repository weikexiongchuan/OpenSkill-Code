# OpenSkill-Code

规范与技能的安装、更新、迁移入口；日常读取 CLAUDE.md。只有用户要求安装或更新才写文件，阅读本文不触发安装。

## 安装与迁移

1. 确定宿主（Codex／Claude）、`<OPEN_SKILL_ROOT>`、个人工作区 `<WORKSPACE_ROOT>` 和接入的项目根目录。使用用户指定或已确定位置，个人工作区与业务仓库分别识别。
2. 自动读取个人工作区已有 AGENTS.md／CLAUDE.md、其明确引用的环境／偏好记录及选定宿主的用户级说明。只采集本机环境、工具路径、个人习惯和索引；不遍历无关目录、会话或凭据。已能查证的事实不逐项追问。
3. 按 [workspace protocol](docs/workspace-protocol.md) 将环境与习惯整理到 `<OPEN_SKILL_ROOT>/workspace/_global/preferences/`，在 `indexes/preferences-index.md` 建索引；沿用已有条目、查重更新，标明本机及来源。此目录本地使用且不进版本库，敏感值不复制；新机器重新发现工具路径。
4. 合并下方完整模板：个人模板写 `<WORKSPACE_ROOT>/AGENTS.md`，项目模板只写用户指定项目的 AGENTS.md。替换路径；已有个人文件中的项目规范按原范围移入对应项目，未知归属仅说明缺口，不猜项目、不丢原文。项目业务参数、特定聊天规则和单次授权不进入通用模板。
5. 在选定宿主实际生效的用户入口加入下方宿主区块：Codex 为 `<CODEX_HOME>/AGENTS.md`（默认 `~/.codex`）；已有非空 AGENTS.override.md 时更新实际生效的 override。Claude 为 `~/.claude/CLAUDE.md`。保留其他工作区规则。
6. 已有同名段先合并；重复安装只更新对应标记内内容，保留标记外定制。明确的新要求按原范围修正旧条目；无依据的冲突只暂停冲突项。换目录更新入口及链接；卸载只移除安装区块，不删个人记录、项目规范或技能库。
7. 分别从个人工作区和实际项目目录验证宿主入口、工作区索引、项目规则、公共入口及命中技能可读；报告写入文件、根路径、技能库提交及未验项，不用数据库或生产操作验证安装。

Codex 的项目发现通常止于 Git 根目录，因此用户入口显式读取个人工作区索引，不能依赖仓库外父目录自动生效。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 项目 AGENTS.md 完整模板

以下为本用户确认的项目工作规范；新项目接入时核对适用范围。已有项目业务、数据和发布参数保留原范围。

```markdown
<!-- openskill-code:project:start -->
## 工作与交付

以下规则限定本项目；来源为用户已确认的开发、排查与发布约定，2026-11-02 整合。

- 需求未明确只做只读排查和必要的最小能力验证，不改正式业务代码、配置或行为测试；实施前核对目标、范围、触发条件和异常分类，已明确的不重问。
- 优先复用现有设计与代码，不新增未要求的功能、开关、门禁、降级或兼容分支；代码、测试及代理方案不能替代用户授权。
- 规则不跨错误分类或业务场景套用。调整方案时在工作记录对照“用户原话／证据、限制原因、原场景、新场景是否成立、保留或移除”，不成立的限制不继承。
- 一流程执行规则且不得影响另一流程时，先核对“触发者 → 读取对象 → 执行点 → 输出 → 下游”；发现冲突说明影响，不擅自迁移执行阶段。
- 目标和授权明确后持续完成；多个需求按用户顺序逐项完成验证，不并行发散。只有实质扩大范围、新增权限或客观阻塞才再问；超时先查瓶颈，不只等待或重试。
- 未经明确要求不新增数据库锁或显式代码锁，包括 FOR UPDATE、命名锁、互斥锁；不据此删除已有锁。（2026-10-30）
- 修改前读适用规范和代码；无项目风格约定时沿用现有风格。复杂实现说明实际原因和边界，不为注释新增未来扩展机制。
- 按风险选择最小验证：低风险小改可只查差异，需要时只验证相关路径；不强制新增测试、全量回归、逐阶段确认或多轮审核。相关文件和依赖未变且核对差异后可复用结果；只有相关变化、失败或新风险才补验。（2026-10-26 至 27）
- 文档交付前核对原要求、事实来源、算术、正文／表格／流程图及样例；代码完成后核对范围和受影响路径。简单修改自查，复杂或高风险方案、协议、规则和代码变更独立复核一次，只复核实质变化。
- 审核独立核对用户原话、授权及最新差异；技术正确不能覆盖范围越界。改表／索引在正式实现前审核必要性、免改表替代、真实规模、执行影响、兼容和恢复，生产执行另取当次授权。
- 异常显式暴露，不新增兜底掩盖错误；业务失败保留已确认的业务语义，敏感异常安全包装。
- 解释接口给出方法、协议、域名、完整路径和查询参数；密钥用占位符。时间、金额、比例注明口径，英文缩写首次附中文。
- 禁止 git reset --hard、git clean -fd、git push --force。

## 数据操作边界

- 未经明确授权不初始化或启动本机数据库，包括开发、测试容器和隔离验证；开发需求不构成该授权。
- 新增／修改 SQL（含 ORM／工具生成）逐条比较最小等价索引路径，核查条件、排序、分页、查询次数、批量边界和在途数量；参数或执行方式改变后重检，不以“有索引”代替效率判断。
- 数据查询先用结构、索引定义或 EXPLAIN 确认索引路径；key 为空或 type=ALL 时不执行数据查询。
- 生产 DDL／DML 执行前列出目标库表、完整操作及影响范围，取得该次明确同意；开发、修复、审核或部署不代替改库授权。

## 排查与文档

- 先明确要判断什么，从用户指定对象和入口查起，已知条件不重问；按结论／证据／影响／待查项呈现，优先表格。判错前核对业务定义、同类频率和正常对照。
- 问题与流程对应、编号一致；说明前端请求或后台触发、失败步骤及受影响结果，不用模块名代替业务影响。
- 提供脱敏对象、时间、当时输入／原始返回、重复或后续恢复证据；区分证实、推断与缺口。无法确认调用方就说明，不能把可能路径当已发生故障。
- 采集说明来源、触发方式、现网频率和再查条件；数据库说明库表、规模口径、查询范围、索引及慢步骤证据，不能用表大或超时堆栈直接归因。
- ERROR 不直接等于缺陷；区分请求失败、数据未就绪、正常链上变化、日志等级及持续故障，结合时效和恢复证据判断。后来数据有效不能证明当时有效，未再报错不能证明恢复。
- 补全／同步等待或反复重试须核对失败子原因、样本输入／原始返回、实际次数与间隔、再次触发及退出条件；区分任务领取与物理调用次数。原因丢失时说明缺口，不能用“还会重试”判正常。（2026-10-28）
- 方案按业务层次组织，短段落、必要小标题和列表，字段定义用表格，重复说明合并。已确认要求作为约束；接口能力等事实由代理查证，缺证据说明影响；只有真实业务取舍列差异及代价。
- 面向读者的正文不写“评审必须确认／待决策”等指令；内部审核和执行记录另放工作记录，不把未经授权的规则作为默认候选。（2026-10-22 至 23）
- 表格先明确阅读汇总或数据分析，不明确才问；两者都需要时分工作表，阅读汇总首页。首页中文表头，优先指定列，补平台及可点击来源；完整哈希、技术字段和证据放分析明细。
<!-- openskill-code:project:end -->
```

## 同步维护

模板为可迁移正文，本地管理区块为实例。`standards-organizer` 必须一起核对归属文件、模板、公共入口和命中技能，修正实际受影响条目及引用，已一致内容不重复改写。个人环境和习惯采集到本地记录，个人工作区保留简短说明及索引；项目规范留项目。

详细方法放 skills／docs，宿主共用 CLAUDE.md 入口。当前通过路径读取技能，不等于注册到宿主技能菜单，注册状态单独报告。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)
