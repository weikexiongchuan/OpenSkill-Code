# OpenSkill-Code

规范与技能的安装、更新、迁移入口；日常读取 CLAUDE.md。只有用户要求安装或更新才写文件，阅读本文不触发安装。

## 安装与迁移

1. 确定宿主（Codex／Claude）、`<OPEN_SKILL_ROOT>`、个人工作区 `<WORKSPACE_ROOT>` 和接入的项目根目录。使用用户指定或已确定位置，个人工作区与业务仓库分别识别。
2. 自动读取个人工作区已有 AGENTS.md／CLAUDE.md、其明确引用的环境／偏好记录及选定宿主的用户级说明。只采集本机环境、工具路径、个人习惯和索引；不遍历无关目录、会话或凭据。已能查证的事实不逐项追问。
3. 按 [workspace protocol](docs/workspace-protocol.md) 将环境与习惯整理到 `<OPEN_SKILL_ROOT>/workspace/_global/preferences/`，在 `indexes/preferences-index.md` 建索引；沿用已有条目、查重更新，标明本机及来源。此目录本地使用且不进版本库，敏感值不复制；新机器重新发现工具路径。
4. 合并下方完整模板：个人模板写 `<WORKSPACE_ROOT>/AGENTS.md`，项目模板只写用户指定项目的 AGENTS.md。替换路径；已有个人文件中的项目规范按原范围移入对应项目，未知归属仅说明缺口，不猜项目、不丢原文。项目业务参数、特定聊天规则和单次授权不进入通用模板。
5. 在选定宿主实际生效的用户入口加入下方宿主区块：Codex 为 `<CODEX_HOME>/AGENTS.md`（默认 `~/.codex`）；已有非空 AGENTS.override.md 时更新实际生效的 override。Claude 为 `~/.claude/CLAUDE.md`。保留其他工作区规则。
6. 已有同名段先合并；重复安装只更新对应标记内内容，保留标记外定制。明确的新要求按原范围修正旧条目；无依据的冲突只暂停冲突项。换目录更新入口及链接；卸载只移除安装区块，不删个人记录、项目规范或技能库。
7. 分别从个人工作区和实际项目目录验证宿主入口、工作区索引、项目规则、公共入口及命中技能可读；报告写入文件、根路径、技能库提交及未验项，不用数据库或生产操作验证安装。

Codex 的项目发现通常止于 Git 根目录，因此用户入口显式读取个人工作区索引，不能依赖仓库外父目录自动生效。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

```markdown
<!-- openskill-code:entry:end -->
```

## 个人工作区 AGENTS.md 完整模板

```markdown
<!-- openskill-code:workspace:start -->
# 个人工作区

仅维护本机环境、个人习惯和索引；项目通用规范、业务约定和操作红线放项目 AGENTS.md 及仓库内引用。

- OpenSkill-Code：`<OPEN_SKILL_ROOT>`；开发、理解项目或维护规范时，先读目标项目规则，再读 `<OPEN_SKILL_ROOT>/CLAUDE.md`，按任务加载技能。
- 环境与习惯：读取 `<OPEN_SKILL_ROOT>/workspace/_global/indexes/preferences-index.md` 及命中条目；工具版本先核对项目声明，换机重新发现路径。
- 沟通用最少文字说明结论、证据和下一步，业务含义先于技术字段；已有明确选择不重复确认。
- 维护归属与同步方式见 `<OPEN_SKILL_ROOT>/skills/30-execute/standards-organizer/SKILL.md`；项目规范不回填到个人文件。
<!-- openskill-code:workspace:end -->
```

## 项目 AGENTS.md 完整模板

以下为本用户确认的项目工作规范；新项目接入时核对适用范围。已有项目业务、数据和发布参数保留原范围。

```markdown
<!-- openskill-code:project:start -->
## 工作与交付

- 目标、范围、触发条件或异常分类未明确，只做只读排查和最小能力验证，不改业务代码、配置或行为测试；已明确的不重问。
- 按授权最小改动、优先复用；不增未要求的功能、开关、门禁、降级或兼容分支，代码、测试和代理方案不代替授权。
- 规则不跨错误分类／业务场景套用；调整方案在工作记录对照“原话／证据、原因、原场景、新场景是否成立、保留／移除”。
- 规则不得影响另一流程时，先核对“触发者→读取对象→执行点→输出→下游”；冲突说明影响，不擅移执行阶段。
- 授权明确持续完成，多个需求按序完成验证；仅范围扩大、新权限或阻塞再问，超时先查瓶颈，不只等或重试。
- 未明确要求不新增锁（FOR UPDATE、命名锁、代码互斥），不据此删已有锁。
- 修改前读规范和代码，沿用现有风格；影响结果的风格选择才问。复杂实现解释原因和边界，不新增未来扩展机制。
- 低风险小改可只查差异，需测试只验相关路径；不强制新增测试、全量回归、逐阶段确认或多轮审核。相关文件和依赖未变且核对差异后可复用结果，仅相关变化、失败或新风险补验。
- 交付核对原要求、来源、算术、正文／表格／流程图、样例及代码影响；简单修改自查，复杂／高风险方案、协议、规则或代码独立复核一次，仅查实质变化。审核须独立对照用户原话、授权和最新差异，技术正确不能覆盖越界。
- 改表／索引先审必要性、免改表替代、真实规模、执行影响及兼容恢复，再写依赖代码；生产执行另取当次授权。
- 异常显式暴露，不增兜底掩盖；保留已确认业务错误语义，敏感异常安全包装。
- 接口说明含方法、协议、域名、完整路径和查询参数，密钥占位；时间／金额／比例注明口径，缩写首次附中文。
- 禁止 git reset --hard、git clean -fd、git push --force。

## 数据边界

- 本机数据库初始化／启动（含测试容器、隔离验证）须明确授权，开发需求不代替授权。
- SQL（含 ORM／工具生成）逐条比较最小等价索引路径，核查条件、排序、分页、次数、批量边界和在途数量；参数／执行方式变化重检，不能只看“有索引”。
- 数据查询先以结构、索引定义或 EXPLAIN 确认索引路径；key 为空或 type=ALL 不执行。
- 生产 DDL／DML 先列库表、完整操作及影响范围，取得当次明确同意；开发、修复、审核或部署不代替授权。

## 排查与文档

- 明确判断目标，从指定对象和入口查起，不重问已知条件；按结论／证据／影响／待查项列表，判错前核对业务定义、频率和正常对照。
- 问题分类、编号与流程对应，说明前端／后台触发、失败步骤和影响；附脱敏对象、时间、当时输入／原始返回、重复／恢复证据，区分证实、推断、缺口。未知调用方不冒充已发生故障。
- 采集说明来源、触发、现网频率及再查条件；数据库说明库表、规模口径、范围、索引及慢步骤，不以表大／超时堆栈归因。
- ERROR 不直接定缺陷；区分请求失败、未就绪、正常链上变化、日志等级和持续故障，结合时效及恢复证据判断。后来的有效数据／不再报错不能证明当时有效／已恢复。
- 等待／重试须核对失败子原因、原始样本、次数／间隔、再触发及退出条件，区分领取与物理调用；原因丢失说明缺口，不凭“还会重试”判正常。
- 方案按业务分层、短段落，字段表格化、重复合并；确认要求直接约束，事实由代理查证、缺证据说明影响，只有真实取舍列差异／代价。正文不写“评审必须确认／待决策”等指令或默认越界候选；审核、执行记录另存。
- 表格先辨阅读／分析，不明才问；兼需则分表、汇总首页。首页中文表头、指定列、平台和来源链接；完整哈希、技术字段及证据进明细。
<!-- openskill-code:project:end -->
```

## 同步维护

模板为可迁移正文，本地管理区块为实例。`standards-organizer` 必须一起核对归属文件、模板、公共入口和命中技能，修正实际受影响条目及引用，已一致内容不重复改写。个人环境和习惯采集到本地记录，个人工作区保留简短说明及索引；项目规范留项目。

详细方法放 skills／docs，宿主共用 CLAUDE.md 入口。当前通过路径读取技能，不等于注册到宿主技能菜单，注册状态单独报告。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)
