# 文档、报告与表格交付

来源：本用户既有约定及 2026-11-02 整合确认。项目规则决定具体约束，本规范提供检查方法，不把方案格式套给其他文档。

## 编写

- 用最少文字说明业务目标、流程、规则和影响；技术字段与代码位置作证据。按业务层次组织，短段落、必要小标题和列表，字段定义用表格，合并重复说明。
- 已确认要求直接作为约束；接口能力等事实由代理查证，缺证据说明影响；只有真实业务取舍列差异及代价。内部审核和执行记录不放面向读者的正文。
- 接口给出方法、协议、域名、完整路径和相关查询参数；敏感值用占位符，来源可点击，样例与真实证据分清。
- 排查先明确判断目标，围绕指定对象和实际入口，列结论／证据／影响／待查项；区分证实、推断和缺口，不把日志等级、单例或展示差异直接定为缺陷。重试问题核对原始返回、物理调用次数、间隔和退出条件。
- 表格先明确阅读或分析用途；两者都要时分表、阅读汇总首页。首页中文表头、指定列、平台及来源，技术字段与完整证据进明细。

## 复核

- 对照用户原话检查范围和来源，核对算术、边界、正文、表格、流程图及样例，先撤回越界内容。
- 简单文字自查；复杂或高风险方案、协议、规则变更由独立子代理复核一次，提供原始要求、确认方案及最新差异，执行 [范围审核](change-scope-schema-review.md) 的适用部分；无改表写“不适用”。工具不可用时如实记录未独立复核。
- 仅复核实质变化，不因文案整理或无关提交重复审核。记录留工作记录，不把文档检查当作业务实现或线上验证。
