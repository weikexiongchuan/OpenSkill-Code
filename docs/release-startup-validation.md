# 发布验收与部署后观察

来源：2026-10-06 发布要求及 2026-10-07、26 至 27 用户修订；2026-11-02 整合。发布入口、备份对象、重启与回滚权限、观察参数由项目规则决定，不跨项目继承。

## 常规发布

- 读取项目规则及实际脚本，核对目标模块、提交、制品哈希和启用组合，按项目要求构建最终包。按 [最小验证原则](testing-scope.md) 选择验证；相关文件和依赖未变且核对差异后可复用结果，旧包不能替代最终包。
- 常规发包不导生产表结构、不做隔离空库启动验收；有数据库变更只验证指定表和受影响路径。本机数据库、生产写入及重启分别遵守授权边界。
- 按项目范围备份、上传校验、切换、健康检查和既有回滚，保留运行时文件。构建、测试、包结构和实际启动分别报告，不互相替代。
- 失败先查首个异常及实际阻塞，按已授权流程恢复，不重复等待重启循环。

## 部署后观察

- 记录提交／制品、备份、覆盖文件、操作起点及重启结果，检查健康、进程稳定性、工作线程／消费就绪、错误日志和本次业务结果，不只看进程或端口。
- 按项目规定的时长、频率、指标和退出条件完成观察，保留时间与结果；未观察完不写成完成，采样缺失不写成成功。缺参数说明证据缺口，不套其他模块时长或新增统一门禁。
- 复用现有监控与日志，区分证实、推断和未验项；观察不自动授权重启、回滚、生产写入或新建定时任务。

## 专项隔离启动验收

仅用户明确要求时执行，不作为每次发包门禁。以下阻断仅适用于本专项：

1. 用最终制品和目标对应运行时、启动方式、profile／业务域，明确外部依赖替换范围，不关闭本次业务域以获得通过。
2. Spring 用真实容器验证装配、配置绑定及初始化，检查候选 Bean、限定符、条件注册、代理和循环依赖；手工 new 或调用 @Bean 不算装配。
3. 只用获准隔离资源，不消费生产队列、不写生产数据、不触发外部业务动作；本机隔离数据库仍需明确授权。
4. 在声明窗口内完成初始化、就绪、健康及进程稳定检查；非 HTTP 服务使用真实就绪信号。失败或缺证据时专项未完成，不能用生产重启替代。
5. 独立审核核对原始证据，仅在相关代码／依赖／启用组合改变后补验受影响部分；证据留已有项目记录，不含敏感值。
