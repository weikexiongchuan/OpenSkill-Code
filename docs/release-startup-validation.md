# 发布包启动验收

来源：2026-10-06 用户要求固定发布流程，避免构建与审核通过但实际发布包无法启动。

## 适用范围

2026-10-07 用户纠正：常规发包不导出生产表结构、不做隔离空库启动验收；有数据库变更时只对指定表做相关测试。保留范围匹配的代码测试、备份、包校验、重启和线上健康检查；问题直接定位并记录，不扩大发布流程。下列隔离验收仅在用户明确要求该项专项验证时执行，不作为每次发包门禁。

测试范围先遵守 [最小验证原则](testing-scope.md)：小修复只做相关验证，已验证且相关文件/依赖未变时可复用结果。提交号变化、无关修改或网络/上传重试不要求重跑全量测试；常规发包保留制品校验、健康和回滚。

## 发包备份范围

2026-10-07 用户约束：发包备份只备份当前 JAR 包，禁止备份整个目录。原有整目录、源码、配置或运行时数据备份要求不再适用于发包；现有发布脚本不符合时，须在下次发包前按此约束调整。

## 专项验收顺序与判据

1. 按项目规则同步最新主分支，确定最终发布提交，再构建、测试和打包；记录提交与实际制品 SHA-256。
2. 核对目标服务的实际启动命令、运行时版本、profile、业务域开关及配置来源；列出本次启用组合和测试组合的差异，禁止以关闭本次启用的业务域来获得通过。
3. Spring 应用必须用真实容器覆盖本次启用组合的依赖装配、配置绑定与初始化；检查新增注入类型在完整应用中的所有候选 Bean、限定符、条件注册、代理类型、循环依赖及 Bean 名冲突。手工 `new` 配置类或调用 `@Bean` 方法不算装配验证。
4. 在隔离环境执行最终发布制品，使用与目标相符的运行时及启动方式，保持本次启用的业务域/profile；允许替换外部连接地址、凭据和隔离数据资源，不得替换待验收的应用配置与 Bean 装配。验证不得连接生产队列消费消息、写生产数据库或触发生产外部业务动作。
5. 发布制品须完成应用初始化、达到项目定义的就绪状态、通过健康检查，且在预先声明的观察窗口内进程不退出或重复重启；记录启动、就绪和健康证据。非 HTTP 服务使用其真实就绪信号，不能只凭进程存在、端口短暂监听或包内类存在判断通过。
6. 独立审核按本规范核对覆盖范围与原始证据；构建成功、单元测试数量、容器测试和包结构检查分别报告，不得互相替代或推导“发布包可启动”。
7. 受影响代码、依赖或启用组合实质变化后，只补相应测试和装配检查；无关提交不触发复测。最终上传制品仍校验 SHA-256，并完成本次实际部署的健康验证。

## 未通过与发布后验证

- 缺少最终包启动证据、实际启用组合未覆盖、初始化失败或健康不通过时，发布验收未完成；停止覆盖线上制品及停止旧服务，先定位阻塞，禁止用生产重启代替发布前验证。
- 无法提供隔离外部依赖时，明确说明缺失依赖与未验证范围，不得关闭业务域、跳过初始化或增加回退分支来声称通过。
- 部署重启后核对实际提交/制品、健康状态、稳定进程及本次业务域的真实工作线程/消费就绪证据；发现启动失败立即查首个异常并按已授权的回滚流程恢复，禁止持续等待重启循环。部署、重启和生产写入仍遵守各自授权边界。

## 证据最小项

- 最终提交、制品路径与 SHA-256、构建和测试命令及结果。
- 目标与隔离环境的运行时、启动方式、profile/业务域组合、外部依赖替换范围。
- 实际容器装配测试、最终包启动命令、观察窗口、初始化/就绪/健康结果、错误日志检查和独立审核结论。
- 证据保留按项目记录要求执行；不记录凭据、完整敏感环境变量或业务原文。未执行项必须明确标为未验证。
