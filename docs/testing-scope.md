# 按改动风险选择最小验证

来源：2026-10-26 至 2026-10-27，用户要求降低测试流程约束：“小的需求，小的调整，自行评估需不需要跑测试，不要把小的变更搞的很麻烦”。适用于本技能集所有测试、回归、审核和发布条款；与旧条目的通用“必须测试”冲突时，以本原则为准。

先判断是否需要测试，再决定测试范围。小需求、小调整和小修复由代理结合行为变化、影响范围、可逆性与已有证据自行评估；低风险且差异自查足以确认时，可以不新增、不运行测试，直接交付。需要测试时只选最相关用例或复现路径，不因任务叫“新需求”就启动完整测试流程。

| 改动 | 默认验证 |
|---|---|
| 文案、注释、说明、简单可逆配置 | 差异检查；涉及语法时做语法检查，不新增行为测试 |
| 范围明确、低风险的小需求、小调整或小修复 | 自行评估是否需要测试；差异自查足够时可不跑。需要时选择相关用例、复现路径或必要的编译；确有防回归价值才补用例 |
| 多模块行为、并发、协议、数据准确性或资源管理变更 | 验证实际受影响路径与关键失败场景；按依赖范围选测试，不自动扩大为全仓 |
| 广泛公共依赖、框架升级、难以界定的系统影响 | 有具体依据时扩大回归；全量测试说明必要性，不能作为所有任务默认步骤 |

- 需求清楚时由代理选择最小充分验证，不逐阶段请求测试策略确认；只有业务语义不清或验证会新增费用、生产写入、范围与权限时再问。
- 不为小需求、小调整或小修复强制基线全量、单元＋集成＋端到端齐全、固定覆盖率、每分支机械用例、独立测试报告或多轮子代理复核。一次有效复现或针对性验证可以足够。
- 同一改动验证通过后即推进交付。只有受影响代码/依赖改变、出现相关失败或新风险证据才补测相应范围；提交号变化、无关提交、说明修改、网络重连、上传重试本身不要求重跑。
- 可复用受影响文件及依赖未变的测试结果，记录原版本和差异核对。最终制品仍须可追溯；生产发布保留备份、制品校验、健康检查及既有回滚能力。脚本若强制重复全量，优先在标准入口复用已有跳测/定向选项，必要时做最小适配，不改用旁路发布脚本。
- 不为验证初始化数据库或调用有副作用的生产接口；原有数据权限、准确性、兼容性和异常处理要求不降低。
- 失败先判定与改动的关系；相关失败修复后只补相关验证，无关已知失败记录即可，不自动阻断独立的小修复。
- 交付简述实际检查或测试及结果；未跑测试时用一句话说明依据，不写成测试通过。小任务无需额外审批、测试计划或独立报告；关键风险不能仅凭改动行数少而忽略。
