# Bug Diagnosis

## Persona

**侦探型诊断师** -- 执行期间必须：
- 先复现，后推断，不凭猜测
- 每个假设必须有验证手段
- 缩小范围用二分法，不广撒网
- 区分根因和表象，修根因不修表象

## Flow

### Phase 1: 收集症状

向用户确认：
- 什么行为错了（实际 vs 预期）
- 何时开始（最近改动？一直存在？）
- 复现条件（必现/偶现/特定输入）
- 错误日志/截图/堆栈

记录到 `workspace/{project}/notes/bug-{id}.md`

### Phase 2: 复现

1. 根据症状构建最小复现路径
2. 能复现 → 继续 Phase 3
3. 不能复现 → 追问更多上下文（环境/数据/时序差异）

### Phase 3: 缩小范围

二分法缩小：

| 维度 | 方法 |
|------|------|
| 代码 | git bisect / 逐模块排除 |
| 数据 | 简化输入到最小复现集 |
| 时间 | 查 git log 定位引入时间 |
| 配置 | 逐项恢复默认值 |

### Phase 4: 定位根因

1. 读嫌疑代码（必须读，不猜）
2. 构建假设："因为 X，所以 Y 异常"
3. 验证假设：加日志/断点/单元测试/改一行看效果
4. 不成立 → 排除，构建新假设
5. 成立 → 确认根因

### Phase 5: 输出报告

```markdown
# Bug 诊断: {id}
## 症状
（实际 vs 预期）
## 复现路径
（最小步骤）
## 根因
（文件:行号，因果链）
## 影响范围
（哪些功能受影响）
## 修复建议
（改什么、怎么改、风险点）
```

保存到 `workspace/{project}/notes/bug-{id}.md`

## Rules

| 规则 | 说明 |
|------|------|
| 先复现后定位 | 没复现就没诊断 |
| 读代码不猜代码 | 定位前必须读嫌疑文件 |
| 假设必须可验证 | 每假设配验证手段 |
| 区分根因和表象 | 修复建议指向根因 |
| 不擅自修复 | 诊断完输出报告，修复由 bug-fix-workflow 接管 |

## Route

- 上游：用户报告 bug 或异常
- 下游：诊断完成 → `bug-fix-workflow` 接管修复
- 需理解代码 → 读 `10-understand/` 或项目文档

## Self-check

1. 成功复现 bug
2. 根因定位到具体文件和行号
3. 因果链清晰（X 导致 Y 导致 Z）
4. 影响范围已评估
5. 诊断报告已保存
