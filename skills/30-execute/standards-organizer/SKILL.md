# Standards Organizer

## Persona

**规范管家** -- 按证据区分规则、事实和候选约束，沿用项目已有位置，不重复维护。

## 触发信号

| 信号 | 示例 |
|------|------|
| 固化意图 | "以后都要..."、"我们的规范是..."、"记住这个约定" |
| 纠正偏差 | "不要这样做"、"这个写法不对，应该..." |
| 项目约定 | "这个项目用的是..."、"我们统一用..." |
| 项目证据 | 当前任务发现可复用的实现事实、候选约束或已有规则与实现的差异；先分类，不直接升级为规范 |
| 技术偏好 | "优先用 X 而不是 Y"、"禁止使用 Z" |
| 回答/产物偏好 | "结论先说"、"不要分点太多"、"方案先给影响范围" |
| 错误处理红线 | "出错必须报出来"、"禁止默认回退"、"不要降级继续执行"、"敏感异常要包装后再抛" |

## Flow

### Step 0: 核实来源与适用范围

按 [项目约束的识别与维护](../../../docs/project-constraint-maintenance.md) 读取任务相关项目规则和证据，区分明确约束、当前事实、候选约束和临时信息。纯事实不写成强制规则，项目规则不自动推广到通用 skill。

### Step 1: 识别类型

先找项目已有维护位置；下表的 workspace 路径仅在没有既定位置且确需记录时使用。存在仓库内规则和索引时直接维护原文件，workspace 只引用，不复制。

| 类型 | 归档位置 | 示例 |
|------|---------|------|
| 语言级通用 | `skills/10-understand/{lang}-dev-standards/SKILL.md` | "Java 禁止用 Lombok" |
| 项目级专属 | `workspace/{project}/notes/project-standards.md` | "API 返回统一用 Result 包装" |
| 项目内可复用能力 | `workspace/{project}/common/index.md` 与命中主题笔记 | "这个查询封装可被多个业务复用，限制在某类索引上" |
| 组件/UI | `workspace/{project}/notes/component-registry.md` | "按钮一律圆角 8px" |
| 测试约定 | `skills/10-understand/{lang}-test-standards/SKILL.md` 或项目级 | "Mock 数据放 __fixtures__" |
| 流程约定 | `workspace/{project}/notes/workflow-standards.md` | "发布前必须跑全量回归" |
| 回答/产物偏好（公共） | `workspace/_global/preferences/*.md` | "先给结论，再给证据" |
| 纠偏后的稳定理解 | `workspace/{project}/notes/` 下主题笔记 | "这两类输出按一套协议处理，不要拆成两套命名" |

### Step 2: 查重

1. 读目标文件，检查是否已有相同或相似规范
2. 已存在且一致 → 跳过，告知已记录
3. 已存在但冲突 → 用户已明确修订且范围清楚时更新原条目；其余按维护规范标明差异，仅澄清受影响决定
4. 不存在 → 追加
5. 仅当信息具备复用价值且相对稳定时才写入；一次性上下文不归档
6. 写入前先压缩成最短可复用条目；过长说明拆成主题条目，不写成长段
7. 同类条目变多时，按主题拆文件，并更新对应索引

### Step 3: 写入

- **通用 skill**：只有本次明确要求修改通用规范且有适用范围依据时，才更新对应 SKILL.md；不能因为在项目中发现一种做法就追加
- **项目级**：更新项目已有规则文档；AGENTS / CLAUDE 保持简短入口并引用详细规则，没有既定位置时按 Step 1 选择
- **事实与候选**：写入已有项目记录，附证据；候选明确标注状态，不进入正式规则或执行门禁
- **项目内可复用能力**：先核实真实代码和适用边界，再更新 `common/index.md`；未实现的约定仍写 `notes/`，不冒充已验证能力
- **公共回答偏好**：写到 `workspace/_global/preferences/{topic}.md`
- **主题纠偏**：写到 `workspace/{project}/notes/{topic}.md`，标题直接体现纠偏后的正确理解
- 格式：短句，一行一条，与已有风格一致
- 写入后同步更新已有索引；采用 workspace 位置时：
  - 公共偏好 → `workspace/_global/indexes/preferences-index.md`
  - 项目笔记 → `workspace/{project}/notes/index.md`
  - 项目可复用能力 → `workspace/{project}/common/index.md`
- 写入后告知：已记录到 {文件路径}

### Step 4: 通知

新规范影响开发流程时，相关执行 skill 的 Phase 0 会自动读取（因为它们读取规范文件）。

## Rules

| 规则 | 说明 |
|------|------|
| 捕捉不打断 | 在正常对话中捕捉，不中断当前任务 |
| 最少 token | 一行一条，不写段落 |
| 查重优先 | 不写重复规范 |
| 冲突核实 | 不重复确认用户已明确的修订；未知冲突不擅自取舍 |
| 来源与范围 | 正式约束保留简短来源和范围；事实附证据，候选标明状态 |
| 纠偏可沉淀 | 用户指出理解/风格/产物问题且具复用价值时，应归档 |
| 临时信息不写 | 没有复用价值或尚不稳定的信息不归档 |
| 先压缩后分层 | 先压缩条目，再按主题拆文件，最后维护索引 |

## Self-check

1. 正确区分规则、事实、候选和临时信息；项目约定没有自动变成通用要求
2. 查重后再写入
3. 写入格式与已有一致
4. 告知用户已记录位置
5. 候选未确认没有阻塞无关工作；没有把文档整理当作业务实现或运行验证
