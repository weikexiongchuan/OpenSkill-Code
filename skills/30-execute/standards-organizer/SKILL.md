# Standards Organizer

先读 [约束维护](../../../docs/project-constraint-maintenance.md) 和适用规则，区分已确认要求、事实、候选与单次决定。

## 归属

| 内容 | 维护位置 |
|---|---|
| 本机环境、工具路径、个人习惯和索引 | 个人工作区 AGENTS.md 简短说明及索引；详细记录沿用已有位置，OpenSkill 本地记录用 workspace/_global/ |
| 项目通用规范、业务选择、操作红线、数据与发布规则 | 项目／模块 AGENTS.md 及仓库内主题文档，不回填个人文件 |
| 通用执行方法、语言规范及检查步骤 | 对应 skills／docs；须有通用修改授权与范围依据 |
| 已验证能力、进度与事实 | 项目已有记录和索引；确需记录且无既定位置才选 OpenSkill workspace |
| 单次操作、特定聊天及临时参数 | 原任务记录，不进入长期模板 |

## 维护

1. 查重、核实来源；已一致就复用。用户明确修订且范围清楚时更新旧条目，不重问；未知冲突只澄清冲突部分，候选不成为门禁。
2. 个人工作区只放环境、习惯和索引；误放的项目规范按原范围移入对应项目。归属未知时保留原文并说明缺口，不猜项目。
3. 安装时按 [安装协议](../../../README.md#安装与迁移) 自动读取已有个人说明及明确引用，整理环境、习惯和本地索引；不采集凭据、扫描无关会话或把机器路径写进分发模板。
4. **一起维护**：规则调整必须同时核对归属文件、README 对应模板、公共入口、命中技能及引用，修正实际受影响项；已一致内容不制造改动。同步范围、触发条件和索引，详细规则只维护一份。
5. 模板保存可迁移规则，本地管理区块为实例；本机事实只改本地记录，项目专属业务及单次授权不进通用模板。新场景记录“原话／证据、原因、原场景、新场景是否成立、保留或移除”。
6. 沿用已有位置和格式，短句、必要表格和链接；不存在的文件不因读取自动创建，只更新变化项和受影响索引。

## 交付

说明更新位置及未同步项，核对个人／项目归属、模板／实例和入口／技能口径。按 [文档交付](../../../docs/document-delivery.md) 复核，不把文档整理当作安装生效、业务实现或线上验证。
